# 第二批截图样本建议

## 建议拆成两个目录

- `recognition-samples/batch-02-coverage`：用于补齐当前没有模板或只有单次观测的内容。
- `recognition-samples/batch-03-blind`：算法冻结后才用于验收，不参与模板生成和阈值调节。

两个目录都继续使用三位数字图片名和现有 `labels.txt` 表头：`id / link / layout / variant / device`。原图保持未裁剪 PNG。

## 数量和设备要求

- 覆盖批建议先提供 8 张：iPhone 17 与 iPad Pro 2024 11 英寸各 4 张。
- 尽量让上面每个未覆盖项目至少出现 2 次，并且至少跨两台设备各出现 1 次；同一截图可以同时覆盖很多项目。
- 数量数字 `0` 和 `7` 当前各只有 1 个可跨卡片提取的字形，建议有意识加入 `x10`、`x7`、`x17` 等数量。无需为了数字破坏 352/11 容量规则，可利用低人口兵种组合。
- 至少保留 2 张负例，例如缺战宠、援军攻城机器为 0/2；负例仍需是完整截图。
- 盲测批建议另取 6 张，每台设备 3 张。不要复制到覆盖批，也不要在盲测前运行模板提取命令。
- 若能增加第三种手机或平板比例，可放入盲测批，用于判断是否需要新增设备画像；当前第一版只承诺两种已知设备。

## 交付格式示例

```text
recognition-samples/batch-02-coverage/
  images/
    001.png
    002.png
  labels.txt
```

```text
id<TAB>link<TAB>layout<TAB>variant<TAB>device
001<TAB>https://link.clashofclans.com/cn?...<TAB>edit<TAB>original<TAB>iphone-17
```

收到覆盖批后的固定处理顺序为：导入/审计 → 面板预处理 → 卡片与英雄子卡自动标注 → 图鉴差异检查 → 模板重建 → 留一法评估。盲测批只运行识别与评估，不进入模板重建。
