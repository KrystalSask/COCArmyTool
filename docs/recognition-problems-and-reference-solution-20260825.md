# 截图识别现存问题与参考解决方案

> 日期：2026-08-25  
> 状态：讨论与实施参考，不代表所有方案已经完成  
> 范围：配兵面板定位、卡片分割、卡片类别识别、数量识别及回归测试

## 1. 文档目的

当前截图识别不是单一模型问题，而是一条多阶段链路：

```text
原始截图
  → 定位配兵面板
  → 按面板相对布局定位各区域
  → 分割单张卡片候选框
  → 识别卡片类别
  → 识别左上角数量
  → 容量与唯一性校验
```

任何上游坐标误差都会传递到下游。例如面板右边界偏窄，会导致区域坐标整体偏移、最右卡片丢失、候选框裁切不完整，最终表现为类别和数量识别错误。因此应先稳定几何定位，再替换类别识别，最后单独处理数字。

## 2. 当前实现概述

### 2.1 面板定位

当前面板定位是规则式视觉算法，不是目标检测模型。主要实现位于：

- [`src/recognition/panelLocator.ts`](../src/recognition/panelLocator.ts)
- [`src/recognition/imageNormalization.ts`](../src/recognition/imageNormalization.ts)

现有算法包含：

- 根据整张截图宽高比选择 iPhone/iPad 设备模板；
- 搜索右上角红色关闭按钮；
- 使用木色区域、边缘强度和预设面板比例为候选框评分；
- 假设自动候选面板宽度通常占整张截图的 72%～102%；
- 假设面板宽高比接近 1.88、1.93 或 1.98；
- 检测失败时回退到预设的归一化设备框；
- 裁出面板后拉伸到固定的 2160×1120 识别画布。

### 2.2 卡片候选框

当前卡片定位继续使用结构规则，包括：

- 面板内固定相对区域；
- 卡片边缘；
- 卡片等间距结构；
- 数量区域和局部边缘作为辅助证据。

布局定义位于 [`src/recognition/layouts.ts`](../src/recognition/layouts.ts)，卡片检测位于 [`src/recognition/cardDetector.ts`](../src/recognition/cardDetector.ts)。

### 2.3 卡片类别识别

当前类别识别不是神经网络分类，而是模板特征匹配：

- 候选卡片归一化为 64×64；
- 屏蔽部分左上角数量和左下角等级区域；
- 计算 dHash；
- 计算 HSV 全局颜色直方图；
- 距离由 65% dHash 和 35% HSV 直方图组成；
- 使用 `1 - distance` 显示为分数。

主要实现位于 [`src/recognition/templateMatcher.ts`](../src/recognition/templateMatcher.ts)，模板特征位于 [`src/data/recognitionTemplates.generated.json`](../src/data/recognitionTemplates.generated.json)。该分数是相似度，不是经过校准的真实概率。

### 2.4 数量识别

当前数量识别使用卡片左上角固定区域和数字位图模板，之后可能由容量约束补全或修正。主要实现位于：

- [`src/recognition/countRecognizer.ts`](../src/recognition/countRecognizer.ts)
- [`src/recognition/countConstraints.ts`](../src/recognition/countConstraints.ts)

## 3. 已确认的主要问题

## 3.1 P0：面板定位依赖固定比例，跨截图来源不稳定

### 表现

- 修正左边界后，其他样本的右边界再次偏窄；
- 视频自身黑边可能被误认为面板边缘；
- 手机截图中，游戏画面可能只是播放器内的一块区域，面板只占整张截图约一半；
- 同一张图片分辨率或宽高比可能对应完全不同的游戏内容缩放比例；
- 自动定位失败后套用设备模板，产生远大于真实面板的黄色框。

### 根因

当前实现把以下概念错误地绑定在一起：

- 截图设备宽高比；
- 视频内容在截图中的位置；
- 配兵面板占整张截图的比例。

例如一张 2622×1206 图片既可能是游戏全屏截图，也可能是带黑边和播放器界面的手机截图。仅靠分辨率和预设比例不能确定面板位置。当前搜索宽度下限为整图的 72%，因此无法表示只占整图约一半的真实面板。

固定拉伸到 2160×1120 还会将面板本身的小幅比例差异转换为内部坐标偏移。

### 影响

面板框是后续所有相对坐标的基准。四条边中的任何一条不准确，都可能造成：

- 区域整体偏移；
- 第一张或最后一张卡片漏检；
- 多张卡片合并成一个候选框；
- 数量和等级区域被裁断；
- 正确图标被不完整裁切后误分类。

## 3.2 P1：卡片候选框仍会合并、漏首项或漏尾项

已出现的实际案例包括：

- 援兵区空中战车、冰人、天使三张卡片被合成一个候选框；
- 主兵种第一张飞龙没有候选框；
- 法术最后一张雷电法术没有候选框；
- 面板边界偏移后，候选框向按钮区或字幕区延伸。

根因包括面板坐标错误、局部边缘受压缩破坏、卡片右侧被下一张卡片覆盖，以及首尾缺少双侧等间距证据。

## 3.3 P1：模板匹配对相似图标和裁切变化不够稳健

已确认的混淆包括：

- 熔岩猎犬被识别为超级气球兵；
- 雪怪被识别为图腾法术；
- 召回法术被识别为急速或狂暴法术；
- 反击卡组被识别为火箭背包。

dHash 对整体轮廓敏感但表达能力有限，HSV 全局直方图丢失空间结构。两张图只要颜色分布和粗略轮廓相似，就可能获得接近的分数。裁切宽度、视频压缩和面板误差还会进一步放大问题。

## 3.4 P1：数量识别与类别、容量推断耦合过深

已出现：

- 天使实际数量为 5，但左上角数字没有被可靠读取；
- 页面最终显示的错误数量可能来自容量规则回填，而不是 OCR 真正读成另一个数字；
- 将 `x` 当作数字存在性锚点会导致没有识别到 `x` 时整段数量丢失；
- 错误类别会使空间容量推断基于错误的单位空间继续修正，形成级联错误。

数量表示“使用了多少个该兵种”，不应该参与决定卡片类别。容量规则也不应在证据不足时静默覆盖识别结果。

## 3.5 P1：现有样本不能直接当作可靠训练真值

当前仓库约有 21 张主要原始标注截图，并从中自动提取出数百个卡片和数字观察。自动提取结果包含已知的漏框、合框和错分类，因此属于待审核伪标签。

现有 `test_data`、装备回归图和已发现问题的截图必须继续作为独立回归样本，不能为了提高当前测试结果而重新加入训练，否则会造成数据污染。

## 4. 参考解决方案

## 4.1 第一阶段：重做面板定位（最高优先级）

### 推荐架构

```text
YOLO26n 单类别粗检测 army_panel
  → 关闭按钮、长直线、木色边缘联合精修四条边
  → 保持比例缩放并填充到标准画布
  → 输出定位置信度和各边证据
```

目标检测只负责在任意截图位置和缩放比例下找到整个配兵面板。规则算法继续负责将粗框精修到像素级。两者职责不同：

- 检测模型解决黑边、播放器、手机/电脑、任意缩放和水印等跨场景问题；
- 边缘规则利用面板直线和关闭按钮获得比检测框更精确的边界。

### 面板数据集

- 类别只有一个：`army_panel`；
- 每张截图只需标注一个矩形；
- 应覆盖手机、电脑、平板、视频黑边、字幕、水印、中英文界面和不同面板占比；
- 可在现有“手动调整面板”旁增加“保存为边界标注”，由程序自动记录坐标，用户不需要手写像素值；
- 同一视频的相邻帧应放在同一个数据划分中，避免训练/测试泄漏。

### 标准化修改

不再把任意面板无条件拉伸成 2160×1120，而应：

```text
保持原始面板宽高比缩放
  → 居中放入标准画布
  → 不足区域填充
  → 同步记录坐标变换
```

### 降级策略

- 检测与边缘证据一致：自动继续；
- 只能得到粗框：允许带少量向外容错，但降低置信度；
- 多个锚点明显冲突：要求手动调整，不能输出高置信错误框；
- 现有设备模板只能作为最后回退，不再作为主要判断依据。

### 验收标准

不能只使用整体 IoU，应分别记录左、右、上、下边界误差：

- 标准约 1900 像素宽面板上，左右平均误差目标不超过 5 像素；
- 极端样本单边误差尽量不超过 10 像素；
- 不允许裁掉真实面板内容，无法确定时可以略微向外保留容错；
- 手机、电脑、带黑边视频截图必须进入独立回归测试。

## 4.2 第二阶段：稳定卡片候选框

面板定位通过验收后，再调整卡片分割：

- 使用卡片左边缘、可见宽度和等间距共同恢复卡片序列；
- 不依赖 `xN` 决定是否存在卡片；
- 对第一张和最后一张使用区域边界与卡片间距补全；
- 当一个候选宽度接近 2～3 个卡片间距时，主动尝试等距拆分；
- 卡片右侧被覆盖时保留可见部分，不把窄卡片错误拉伸；
- 候选框映射应使用面板标准化过程中记录的坐标变换。

验收应分别统计：

- 卡片应有数量与实际数量；
- 漏框数；
- 多框数；
- 合并框数；
- 首项和尾项召回率。

## 4.3 第三阶段：制作卡片分类数据集

项目已经具备 ID 和标准图标：

- ID 目录：[`src/data/gameData.generated.json`](../src/data/gameData.generated.json)
- 图标：[`public/game-icons`](../public/game-icons)
- 小型审核数据集：[`artifacts/card-classification-mini-v1`](../artifacts/card-classification-mini-v1)

针对固定 UI 卡片，可以采用“一类一张标准图标 + 定向合成增强”的低标注方案。合理增强包括：

- 右侧逐步被覆盖；
- 数量保留、替换或遮挡；
- 等级保留、替换或遮挡；
- JPEG/WebP 压缩；
- 轻度模糊和缩放重采样；
- 少量候选框位置偏差。

不应使用游戏界面不可能出现的旋转、镜像和大幅透视变化。

合成样本用于训练，真实截图用于验证。由同一张标准图生成的增强图片不能同时充当训练集和验证集。

## 4.4 第四阶段：训练卡片分类模型

首选基线为 `YOLO26n-cls`：

```text
单张卡片候选图
  → YOLO26n-cls
  → Top-3 类别及分数
  → 根据卡片所在区域过滤不可能类别
```

区域约束包括：

- 主军队区只允许兵种；
- 主法术区只允许法术；
- 攻城机器区只允许攻城机器；
- 援兵混排区允许兵种、法术和攻城机器，但结合卡片框样式判断类型；
- 装备和战宠使用各自类别集合。

训练时先冻结大部分预训练主干，只训练分类头；之后用低学习率解冻末端层。先评估 `n-cls`，只有准确率或混淆矩阵仍不满足要求时再比较 `s-cls`。

分类模型不读取或输出数量。数量和等级区域应在训练中随机保留、替换或遮挡，避免模型把 `x5`、等级 14 等伪相关当成类别特征。

## 4.5 第五阶段：独立处理数字数量

数量链路应独立为：

```text
卡片左上角固定区域
  → 定位数字区域
  → 忽略可选的 x
  → 分割并识别 0～9
  → 按横坐标组合为最终数量
```

第一版继续改进当前数字模板或使用轻量 0～9 分类器。如果视频压缩导致数字粘连、断裂，无法稳定分割，再追加 `YOLO26n` 小型数字检测模型，直接检测 10 个数字类别。

不建议将 `x1`、`x2`、`x3` 等每个完整数量作为独立类别，否则类别数量会随数量范围增长。

容量和唯一性规则最后只负责：

- 标记总容量不足或超出；
- 给出可能的修正建议；
- 在类别置信度高且数学上只有唯一解时提供明确标记的推断结果。

默认不应静默覆盖原始识别。

## 5. 推荐执行顺序

```text
阶段 0：冻结并整理真实回归样本
阶段 1：面板检测模型 + 四边精修 + 保持比例标准化
阶段 2：修复卡片合并、漏首项和漏尾项
阶段 3：扩展完整卡片分类数据集
阶段 4：训练并集成 YOLO26n-cls
阶段 5：独立改进数量识别，必要时追加小模型
阶段 6：端到端回归、置信度校准和人工降级策略
```

在阶段 1 和阶段 2 通过前，不应急于扩大正式分类训练集，因为错误的面板和卡片裁切会直接污染训练数据。

## 6. 回归测试与数据隔离

建议建立以下相互独立的数据集合：

| 集合 | 用途 | 是否参与训练 |
| --- | --- | --- |
| 面板定位训练集 | 训练 `army_panel` 检测 | 是 |
| 面板定位验证集 | 调参和选择权重 | 否，仅验证 |
| 面板定位回归集 | 手机、电脑、黑边等历史问题 | 否 |
| 合成卡片分类集 | 训练卡片类别模型 | 是 |
| 真实卡片验证集 | 检查合成到真实的差异 | 否，仅验证 |
| 数字训练集 | 训练数字分类或检测 | 是 |
| 端到端截图回归集 | 验证完整识别链路 | 否 |

每次修改都应至少输出：

- 面板四边误差；
- 卡片检测召回率和合并框数量；
- 卡片分类 Top-1、Top-3 和混淆矩阵；
- 数字逐位准确率和最终数量准确率；
- 完整方案容量一致率；
- 相比修改前新增和消失的错误案例。

## 7. 已有改动与仍待解决事项

### 已有或部分完成

- 卡片定位已从纯 `xN` 依赖转向边框与等间距结构；
- 增加了同一区域重复类别的候选冲突处理；
- 候选确认流程已支持更集中的确认操作；
- ID 60 反击卡组和 ID 53 火箭背包加入真实截图特征回归；
- 已建立一组小型“一类一图 + 定向增强”审核数据集。

### 尚未完成

- 面板定位仍未跨手机、电脑和播放器场景稳定；
- 固定 2160×1120 拉伸尚未改为保持比例映射；
- 卡片首尾漏检和多卡合并仍需在正确面板基础上验证；
- `YOLO26n-cls` 尚未训练和集成；
- 数量识别仍依赖现有模板与容量纠正；
- 当前相似度分数尚未进行置信度校准；
- 真实回归集的边界真值和逐卡真值仍需系统保存。

## 8. 当前结论

当前问题不能仅靠继续添加单个模板或设备比例补丁彻底解决。推荐的最终识别架构是：

```text
YOLO26n 定位整个面板
  + 规则算法精修四边
  + 结构算法分割卡片
  + YOLO26n-cls 识别固定卡片类别
  + 独立数字识别
  + 容量规则只做校验和明确标记的建议
```

近期最高优先级是稳定面板定位，并建立可以量化四条边误差的回归测试。只有上游几何稳定后，分类模型和数字模型的训练结果才具有可信度。
