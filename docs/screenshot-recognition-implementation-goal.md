# 截图识别实现 Goal：复用调查与执行基线

## 范围

- 只支持当前国服常驻单位；临时和历史活动单位不进入候选集。
- 输入为完整、未裁剪的横屏游戏截图。
- 第一批设备：iPhone 17 与 iPad Pro 2024 11 英寸。
- 浏览器本地识别，不上传截图，不依赖账号、玩家标签或服务器。
- 不实现二维码、部署、提交或推送。

## 可复用能力调查

### Supercell 官方 API

官方 API 适合玩家、部落、战争、排行榜等在线资料查询，但没有截图识别、军队配置截图、配兵分享链接解码或完整静态图鉴接口。它还需要 API 凭证和网络请求，与本项目“匿名、本地识别截图”的核心路径不匹配。

结论：运行时不接入官方 API。这样也避免要求玩家提供标签、账号或网络权限。

### clashy.py

`clashy.py` 使用 MIT 许可证，包含当前游戏静态数据模型以及 `ArmyRecipe` 配兵链接解析器。本项目复用它的 `static_data.json` 作为图鉴更新源，并使用自动筛选和差异审计生成前端数据。

其 Army Link 解析器可以作为开发期交叉验证工具，但不直接进入网页运行时，原因是：

- Python 依赖不适合纯浏览器应用；
- 当前实现忽略大守护者 `m` 模式的具体值；
- 没有把主军队中的攻城机器拆成独立类别；
- 项目现有 TypeScript 编解码器已有更严格的格式、重复区段和回环校验。

结论：复用静态数据和解析语义作为测试预言机，保留并加强现有 TypeScript 编解码器。

### clash-of-clans-data

该 MIT TypeScript 包提供结构化数据和图片，设计可参考，但当前公开清单仍缺少废墟女巫、愤怒法术和空中战车，不能作为当前国服协议 ID 的主数据源。

结论：仅作为人工复核和类型设计参考，不引入依赖。

### OpenCV / OpenCV.js

OpenCV 使用 Apache-2.0 许可证，适合面板定位、边缘/轮廓检测、模板匹配、直方图和离线评估。本批样本是数字截图，不存在相机透视和镜头畸变，因此第一版无需立即把完整 OpenCV.js/WASM 包加入网页。

结论：开发期预处理与评估使用本机 Python OpenCV；浏览器端先用 Canvas 像素操作实现相同的确定性步骤。若后续出现更多分辨率、压缩或偏移导致 Canvas 版本不稳，再引入本地打包的 OpenCV.js 子集。

### Tesseract.js

Tesseract.js 是 Apache-2.0 的浏览器 OCR，但本任务只需要识别卡片左上角的 `x0123456789`，字体固定、区域固定、字符集合极小。通用 OCR 的语言模型、初始化时间和包体积都没有必要，并且其项目范围不包含针对本游戏字体修改核心模型。

结论：不引入。使用二值化、连通域分割和专用数字模板分类器。

### ONNX Runtime Web

ONNX Runtime 使用 MIT 许可证，可在后续加载轻量分类模型。当前只有 13 个样本，不足以合理训练覆盖 136 类图鉴的模型。

结论：保留现有可替换引擎接口；只有经典匹配在扩充样本后仍达不到指标时，才训练小型图标分类器并用 ONNX Runtime Web 推理。

## 第一版技术路线

1. 无损导入原图和链接，记录 SHA-256、设备、分辨率、布局与图鉴版本。
2. 将“样本文件完整性”“图鉴是否覆盖”“是否满足导出条件”分开审计；不满配截图仍可作为识别负例。
3. 依据灰色标题栏、棕色面板边界和容量图标定位有效面板；设备配置只提供初始搜索窗口，不作为唯一判断。
4. 将面板归一化到统一坐标，按主部队、主法术、主攻城、城堡援军混排行和英雄区分区。
5. 用卡片蓝/紫/金边和连续槽位检测卡片；不依赖 OCR 读取名称。
6. 利用配兵链接中条目顺序与游戏卡片显示顺序提取带标签的截图原生模板，并与本地真实图标共同组成候选库。
7. 图标匹配组合使用遮罩后的归一化相关、颜色直方图和感知哈希；每个区域只与允许类别比较，输出 Top-3。
8. 左上角数量区域单独二值化，使用 `x0–9` 模板识别；左下角等级徽章全部屏蔽。
9. 英雄不识别皮肤立绘：两件装备的共同归属推断英雄，战宠独立匹配，大守护者角标单独识别地面/空中。
10. 所有低置信度或冲突项进入人工确认；容量、装备归属、宠物唯一性和链接回环全部通过后才可复制链接。

## 评估拆分

- 面板定位：IoU、四边像素误差、布局/设备识别准确率。
- 卡片检测：按区域统计 precision、recall、漏检和多检。
- 图标：Top-1、Top-3、类别混淆矩阵。
- 数量：字符准确率与完整数量准确率。
- 英雄部分：装备、战宠、守护者模式分别统计。
- 端到端：完全正确率、平均人工修正数、错误导出次数。

## MVP 验收门槛

- 13 张开发样本全部完成面板和区域提取，不因 iPad 比例被拒绝。
- 卡片无静默漏检；检测不确定时必须要求确认。
- 已覆盖图标在开发样本上 Top-3 达到 100%，Top-1 目标不低于 95%。
- 数量完整值准确率目标不低于 98%。
- 大多数样本需人工修正 0–2 项。
- 未确认、容量无效、装备冲突或回环不一致时绝不导出。
- 第二批盲测样本在算法冻结后再加入，不能参与模板调参。

## 维护规则

- 每次游戏更新先升级静态元数据并运行 `npm run catalog:audit`。
- 图鉴差异未解决时，截图识别候选库构建失败。
- 常驻与活动单位分开；活动单位不进入本项目候选集。
- 原始样本、派生裁片和报告不进入 `public`、PWA 缓存或生产构建。
