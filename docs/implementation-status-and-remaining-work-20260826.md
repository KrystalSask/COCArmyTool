# 截图识别两项改造：当前状态与剩余工作

> 更新时间：2026-08-26  
> 当前状态：暂停实现，等待方向核实  
> 依据文档：`single-card-segmentation-implementation-plan.md`、`army-card-model-ocr-integration-plan-20260825.md`

## 1. 本轮工作的目标

本轮同时推进了两个相互衔接、但职责必须分离的核心模块：

1. **区域定位与单卡分割模块**：从完整截图中定位军队面板，划分兵种、法术、攻城器、城堡军队和英雄区域，并生成稳定的单卡槽位及英雄子卡框。
2. **右侧军队卡片识别模块**：对已经分割出的兵种、法术、攻城器和城堡军队卡片，使用 ONNX 分类模型识别类别，使用 PP-OCRv6 识别 `xN` 数量。

两者的约束是：**几何分割决定卡槽是否存在；模型和 OCR 只识别槽位内容，不能用 OCR 数量、容量推断或规则校验反向增加、删除或移动卡槽。**

## 2. 已确认的识别边界

### 2.1 使用新模型的区域

- `mainTroops`：主兵种
- `mainSpells`：主法术
- `mainSiege`：攻城器
- `castleArmy`：部落城堡中的兵种、法术和攻城器

这些区域使用：

- `army-card-classifier-cn-v2.onnx` 识别卡片类别；
- PP-OCRv6 recognition ONNX 识别卡片数量；
- 原模板分类和位图数量识别仅作为各自独立的降级路径。

### 2.2 不使用新模型的区域

- 英雄
- 英雄装备
- 战宠

装备和战宠仍使用项目原有的模板/视觉特征识别方法。当前实现没有把 76 类军队卡片模型用于装备或战宠，后续也不应这样扩展。

## 3. 已完成的主要工作

### 3.1 区域定位与单卡分割

- 增加多面板候选，不再只依赖一个早期确定的面板框。
- 增加内部结构评分与候选选择，综合卡片行、英雄列等证据选择实际分析面板。
- 将截图统一映射到标准识别空间，降低不同分辨率和黑边对固定布局投影的影响。
- 改进普通卡片槽位检测，并输出槽位几何、角标、蓝框等诊断信息。
- 增加英雄区域局部几何分析，保留四列英雄、八个装备框和四个战宠框。
- 分离“已经分割出框”和“内容识别成功”两种状态；低分战宠或装备冲突不再导致几何框消失。
- 保留装备和战宠的原有视觉识别链，并针对已有样本做过装备回归修正。

### 3.2 军队卡片分类与数量 OCR

- 引入 `onnxruntime-web`，在 Worker 中使用 WASM 执行推理，避免在 UI 主线程直接运行 ONNX。
- 增加模型资源准备脚本、哈希校验、模型 manifest、字符表及上游许可证文件。
- 实现与训练一致的 160×160 左对齐/右填充 RGB 分类预处理。
- 实现 76 类分类后处理，并按当前区域过滤不合法类别后重新归一化概率。
- 实现数量角标裁剪、PP-OCRv6 预处理、CTC greedy 解码及 1～99 数值校验。
- 分类与 OCR 可分别失败并分别降级，不会因其中一个模型失败而关闭另一个模型。
- UI 和测试诊断中可区分类别来源、数量来源、OCR 原文、预处理版本和规则告警。
- 容量与重复规则改为只告警或给建议，不再静默改写 OCR 结果。
- 更换图片时增加过期结果保护，降低异步识别覆盖新图片的风险。
- PWA 对模型和 WASM 使用运行时缓存；大模型不进入首屏预缓存，Tauri 构建仍会包含公开资源。

## 5. 当前正在处理的问题

### 5.1 根因

旧的尾槽清理逻辑会依据 OCR 是否读出数量、容量是否已经满足等信息删除尾部卡槽。这会造成：画面中确实存在卡片，但只因 OCR 暂时没有读出数量就被分割模块删除。

该行为违反已确认的职责边界，因此当前已将 `trimTrailingFalseSlots` 改为不再依据 OCR、容量或重复规则删除槽位。

### 5.2 暴露出的真实几何问题

移除上述错误耦合后，检测器中原本被 OCR/容量规则掩盖的“尾部假槽位”显现出来：

- 样本 4 的城堡军队区域会把右侧操作按钮误认为第 8 张卡片。
- 早期曾怀疑样本 3 的主攻城器区域多检测了一个右侧边缘假槽位；重新核对原图和当前诊断后确认该区域实际有三张真实攻城器卡片，均带可见 `x1`，此前判断已过时。
- 样本 2 中则确实存在第二个攻城器槽位，即使其数量未被 OCR 读出，也必须保留。

城堡军队的假槽位具有明确的结构证据：真实卡片有蓝色卡框，假槽位的 `blue-frame` 比例接近 0。为城堡区域增加仅依赖几何的尾槽过滤后，样本 4 的假槽位可删除，同时样本 2 的真实攻城器仍保留。

### 5.3 当前未完成的错误尝试

此前工作区把同一套 `blue-frame < 0.04` 尾槽规则同时启用到了 `castleArmy` 和 `mainSiege`。这对 `mainSiege` 不成立：真实攻城器卡片也可能测得很低的蓝框比例。

最新的定向测试因此出现回退：

- 样本 1 的主攻城器从期望 3 个被误删到 1 个；
- 样本 6 的主攻城器从期望 3 个被误删到 1 个。

现已撤销 `mainSiege` 对城堡专用蓝框规则的复用，同时保留 `castleArmy` 的结构过滤。样本 1、2、3、6 的攻城器槽数分别为 3、2、3、3；其中样本 3 原图确认三槽都是真实卡片。因此当前没有证据支持再增加攻城器专用尾槽删除规则，除非后续出现带明确人工真值的反例样本。

本次攻城器诊断证据：

- 样本 1：3 个 `badge` 实测槽，三个数量均为 `1`；蓝框比例均接近 0。
- 样本 2：2 个 `edge-sequence` 几何槽；第二槽数量未读出但原图中真实存在，必须保留。
- 样本 3：3 个 `badge` 实测槽，三个数量均为 `1`，原图可见三张真实攻城器卡片；蓝框比例均接近 0。
- 样本 6：3 个 `badge` 实测槽，三个数量均为 `1`；蓝框比例均接近 0。

### 5.4 视频截图战宠回归

该回归已在原有战宠模板/视觉特征链中修复，没有使用军队卡片 ONNX 模型。实际诊断显示并非只有一个低分候选：视频压缩使第 2～4 列真实战宠的 Top-1 分数降到 `0.667/0.604/0.659`，但分别领先第二名 `0.060/0.071/0.109`。13 个原始样本中的唯一空战宠槽 Top-1 为 `0.580`、Top-2 为 `0.578`，分差仅 `0.002`。

因此识别门槛改为：分数至少 `.68` 时直接接受；分数在 `.60～.68` 时，只有 Top-1 至少领先第二名 `.04` 才接受。视频截图已恢复四个战宠，13 个原始样本的战宠真值保持不变。

## 6. 对改造价值的当前结论

重新实现区域提取和单卡分割是有用且必要的，原因如下：

- 它已经降低单一面板框误差向所有下游区域传播的风险。
- 它让黑边、字幕、不同分辨率和小幅边界扰动有了结构化处理入口。
- 它能够保留“框已找到但识别低分”的装备/战宠信息，诊断能力比原逻辑更强。
- 它为 ONNX 分类和 OCR 提供了稳定且可追踪的输入，并让模型错误与几何错误可以分别定位。
- 当前攻城器回退不是这一路线无效，而是一个城堡区专用几何规则被错误泛化到了攻城器区，修正范围明确。

因此建议保留整体架构，不回退到旧的 OCR/容量驱动删槽逻辑；只收紧区域专用的尾槽判定。
