# COCArmyTool 项目说明

## 1. 项目定位

COCArmyTool 是一套面向《部落冲突》国服 18 级大本营玩家的本地配兵数据工具。它解决三个相互关联的问题：可靠解析和生成配兵分享链接、以统一规则编辑并校验完整军队配置、在不上传截图的前提下辅助录入游戏画面。

项目提供两个运行外壳：React/Vite 网页版（可作为 PWA 安装）和复用同一前端、领域逻辑与数据模型的 Tauri 2 Windows 桌面版。

## 2. 范围边界

### 当前支持

- 国服 `CopyArmy` 链接中的 `h / i / d / u / s` 区段。
- 当前 18 本主军、法术、攻城机器、援军和四位英雄规则。
- 常驻兵种、法术、英雄、战宠和英雄装备的简体中文名称与本地图标。
- 本机 IndexedDB 方案库、JSON 备份和恢复。
- 指定 iPhone/iPad 横屏布局的本地截图识别与人工确认。

### 明确不在当前范围

- 低本容量、解锁条件和历史/季节性临时单位。
- 玩家账号、服务端同步、云备份或跨设备实时同步。
- 运行时联网榜单或自动抓取创作者内容。
- 无人工复核的截图到链接全自动导出。

## 3. 核心架构

```text
React 页面与组件
       │
       ├── 领域层：链接编解码、容量计算、合法性校验
       ├── 识别层：预检、布局定位、卡片/数量/英雄推断、复核状态
       ├── 数据层：游戏静态数据、中文词表、热门方案、识别模板
       └── 存储层：Dexie / IndexedDB、备份导入导出
                         │
                  浏览器 / Tauri WebView
```

### 设计约束

1. 解析器只负责尽可能无损地还原协议内容，不把业务合法性混入解析过程。
2. 容量、英雄、战宠和装备规则由独立校验层统一判断。
3. 页面按钮必须消费校验结果，不能自行绕过规则生成可复制链接。
4. 截图识别输出是候选而不是事实；真实候选默认进入人工确认。
5. 数据库名和备份格式属于兼容性接口，重命名产品时不得随意更改。

## 4. 主要数据流

- 链接导入：分享链接 → 协议解析 → 结构化配兵 → 独立校验 → 编辑/保存 → 规范化链接生成 → 回环校验。
- 截图导入：本地图片 → 文件预检 → 面板定位 → 卡片与数量候选 → 英雄归属推断 → 人工确认 → 结构化配兵 → 独立校验。
- 本地方案：编辑结果 → Dexie → IndexedDB → JSON 备份；导入时校验格式和版本，再根据记录 ID 与更新时间合并。

## 5. 数据所有权与隐私

- 用户方案和待识别截图不发送到项目服务器；项目也没有后端。
- 原始回归数据集会进入公开仓库，用于复现识别结果，不进入生产包。
- 新增公开样本前，维护者必须确认截图不包含不应公开的身份信息或聊天内容。
- 游戏图像和商标仍归各自权利人所有，项目许可不覆盖这些素材。

## 6. 成功标准

- 同一合法链接可以完成解析 → 生成 → 再解析而不丢失关键配置。
- 所有可复制链接都通过六项容量与英雄配置校验。
- 截图识别无法可靠确定的内容会显式要求确认，而不是静默猜测。
- 网页版和桌面版共用一套行为与测试，不维护相互分叉的业务实现。
- 维护者可以根据 `docs/MAINTENANCE.md` 重建数据、执行回归并发布版本。
