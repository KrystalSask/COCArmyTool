# 配兵截图单卡分割实现计划

## 1. 文档目的

本文档规划截图识别第一阶段的改造：在不增加新检测模型、不推翻现有分类与配兵校准流程的前提下，提高配兵面板定位、区域配准和单卡候选框生成的稳定性。

当前第二阶段的兵种分类、装备与战宠模板匹配，以及第三阶段的人工校准、容量检查和配兵方案生成整体可用。本轮工作的重点是保证第一阶段能够稳定向第二阶段提供位置正确、内容完整的单卡裁剪。

## 2. 已确认约束

- 输入始终为横屏完整游戏画面，无旋转。
- 允许存在常规视频黑边、字幕、水印和压缩失真。
- 配兵面板完整展开，不考虑弹窗遮挡。
- 识别范围覆盖“我的军队”“已保存配置”“准备进攻”等当前已支持布局。
- 第一阶段最终输出到单卡粒度，而不只是五个大区域。
- 普通兵种、法术、攻城机器和援兵继续优先复用现有卡片分割逻辑。
- 允许同一位置保留少量几何候选，并使用现有分类器或模板分数帮助选择。
- 准确率优先，性能优化放在功能稳定之后。
- 手动校准仍只允许调整整个配兵面板，不新增区域或单卡拖拽。
- `recognition-samples/test_data` 中的 1～13 作为主要测试集。
- 样本 11、12 属于正常视频截图，不能作为极端输入绕过。
- 当前场景中四名英雄、装备和战宠均完整可见，不处理合法缺失状态。

## 3. 当前问题

### 3.1 单一面板框成为全流程单点故障

现有流程较早确定唯一面板框，并将其拉伸到固定的 `2160×1120` 标准画布。后续所有区域都依赖这一全局变换。面板框任意一条边发生少量误差，都会造成英雄底部装备和战宠区域的明显偏移。

### 3.2 面板外框存在视觉歧义

游戏界面包含灰色外框、木纹内容区、卡片边缘、长分隔线、视频黑边和字幕等多层强边缘。仅选择最强边缘不能保证选中后续标准布局所使用的那一层边界。

### 3.3 英雄区域采用固定小矩形取样

装备和战宠框直接由标准坐标投影，没有先检测四列英雄和底部装备行的局部位置。视觉上很小的面板误差可能使模板裁剪混入卡框、相邻图标或背景。

### 3.4 分割状态与识别状态混合

战宠低于阈值、装备归属冲突或任一候选缺失时，整列英雄会从最终结果中删除。界面上的紫色框因此表示“完整识别成功”，而不是“已完成分割”，给用户造成区域没有被检测的印象。

## 4. 目标与非目标

### 4.1 目标

- 将面板外框降级为粗定位，不再要求其独立达到像素级准确。
- 通过多个内部锚点和重复结构完成标准布局配准。
- 为每个面板候选生成完整的区域与单卡分割结果。
- 使用几何完整性和现有识别结果共同选择最佳候选。
- 让手动面板框在存在少量误差时仍能稳定产生单卡框。
- 分离“已经分割”和“已经识别”两种状态。

### 4.2 非目标

- 不新增面板检测神经网络或级联模型。
- 不重新训练现有兵种分类模型。
- 不重写配兵校准、容量约束和链接生成逻辑。
- 不增加区域级或单卡级手动拖拽交互。
- 本阶段不优先优化运行时间和内存占用。

## 5. 目标流水线

```text
原始截图
  -> 游戏画面裁剪
  -> 生成多个粗面板候选
  -> 高分辨率内部锚点配准
  -> 投影五个功能区域
  -> 普通卡片分割 + 英雄区域局部配准
  -> 现有分类器与模板匹配
  -> 综合评价各个分割候选
  -> 选择最佳面板与单卡框
  -> 现有校准、容量检查和配兵方案生成
```

该流程保留逻辑上的三个阶段，但允许第二阶段的置信度反向验证第一阶段候选。反向验证只用于候选排序，不改变分类器职责。

## 6. 数据结构设计

建议新增或扩展以下中间结构。字段名称可在实现时根据现有类型体系调整。

```ts
interface PanelAnchorEvidence {
  kind: 'close-button' | 'header' | 'capacity-row' | 'divider'
    | 'hero-columns' | 'equipment-row' | 'panel-edge'
  rect: NormalizedRect
  score: number
}

interface PanelCandidate {
  id: string
  panel: NormalizedRect
  source: 'close-button' | 'structure' | 'manual'
  geometryScore: number
  anchorEvidence: PanelAnchorEvidence[]
}

interface SegmentedHeroColumn {
  index: number
  rect: NormalizedRect
  equipmentRects: [NormalizedRect, NormalizedRect]
  petRect: NormalizedRect
  geometryScore: number
}

interface SegmentationCandidate {
  panelCandidate: PanelCandidate
  regions: DetectedRegion[]
  cardSlots: DetectedCardSlot[]
  heroColumns: SegmentedHeroColumn[]
  structureScore: number
  recognitionScore: number
  consistencyScore: number
  totalScore: number
  warnings: string[]
}

interface ScreenshotSegmentationResult {
  viewport: NormalizedRect
  selected: SegmentationCandidate
  alternatives: SegmentationCandidate[]
}
```

第一阶段必须保留所有已经分割出的英雄、装备和战宠框。识别失败只能影响候选内容和置信度，不能删除分割框。

## 7. 详细实施步骤

### 阶段 A：建立诊断基线

目的：先观察各阶段误差，避免继续通过最终紫框盲目调参。

任务：

1. 为面板定位输出候选来源、面板坐标和分项评分。
2. 记录五个区域的投影坐标和普通卡槽数量。
3. 记录四列英雄、八件装备、四个战宠的取样坐标。
4. 记录装备最高候选、归属英雄、战宠最高分及被过滤原因。
5. 在调试模式中显示所有分割框，包括识别不完整的英雄列。
6. 保存样本 1～13 的基准结果，重点记录样本 11、12。

完成条件：能够明确回答每个失败样本是面板候选错误、区域投影错误、单卡边界错误还是识别分数不足。

### 阶段 B：多面板候选生成

目的：避免第一个启发式结果直接决定后续全部坐标。

任务：

1. 将面板定位接口由单一结果扩展为候选列表。
2. 以红色关闭按钮中心作为主要搜索起点，但不再使用按钮红色填充尺寸作为唯一比例尺。
3. 根据合理面板宽高范围生成不同平移和比例候选。
4. 使用顶部标题栏、木纹覆盖、外框边缘和画面覆盖率进行初筛。
5. 结构回退路径也返回候选，不直接替换为固定默认框。
6. 对高度重叠候选执行去重，保留约 3～5 个候选进入下一阶段。

完成条件：样本 1～13 的正确面板附近至少存在一个候选，暂不要求候选排序完全正确。

### 阶段 C：高分辨率内部配准

目的：从“外框边缘检测”升级为“标准布局结构配准”。

任务：

1. 保留 512 像素分析用于快速粗定位。
2. 对入选候选使用约 1024～1536 像素宽的分析图进行精修。
3. 将标准布局中的以下结构投影到候选面板：
   - 关闭按钮中心；
   - 顶部标题栏和页签边缘；
   - 主军队、法术、攻城机器和援军容量标题；
   - 主要水平分隔线；
   - 四个重复英雄列；
   - 底部装备行。
4. 分别优化水平缩放、垂直缩放、水平平移和垂直平移。
5. 不启用旋转或透视变换，除非后续样本证明轴对齐变换不足。
6. 对字幕、黑边和游戏内红色通知角标设置负向证据。

初始评分建议：

```text
关闭按钮与顶部结构       20%
木纹与面板内外变化       15%
主要水平分隔线           20%
四列英雄重复结构         20%
装备行结构               15%
外框与覆盖率             10%
```

权重需要通过样本回归调整，不作为固定业务规则。

完成条件：样本 11、12 不再因为字幕或内部强边缘选择明显错误的右边和底边。

### 阶段 D：复用普通单卡分割

目的：保持当前已经稳定的卡片分割能力。

任务：

1. 将每个候选面板标准化到现有 `2160×1120` 画布。
2. 继续调用当前普通卡片边缘与间距检测。
3. 为每个区域记录以下结构指标：
   - 卡片数量；
   - 卡片宽高离散程度；
   - 卡片间距离散程度；
   - 卡片重叠和越界情况；
   - 数量角标可读比例；
   - 分类器最高候选分数。
4. 不使用固定卡片数量淘汰候选，因为实际配兵数量可变。
5. 只对明显不可能的结构进行惩罚，例如大面积重叠、负尺寸和严重越界。

完成条件：现有正确样本的普通卡片数量不回退，并能为不同面板候选提供可比较的结构分数。

### 阶段 E：英雄区域局部配准

目的：降低装备和战宠对全局面板边界的敏感度。

任务：

1. 使用标准位置预测四列英雄的大致区域。
2. 在预测附近搜索共享的水平偏移、垂直偏移、列间距和装备行基线。
3. 通过四列重复竖边和八个装备小卡框的边缘证据评价几何候选。
4. 由选定的共享几何生成八个装备框和四个战宠框。
5. 对整个英雄区域保留少量局部偏移候选，不让十二个小框完全独立搜索。
6. 使用现有装备模板和战宠模板对局部候选排序。
7. 战宠低于当前阈值时保留框和低分候选，不在分割阶段删除。

完成条件：正确面板附近的小幅平移或缩放不会导致四列英雄框整体消失。

### 阶段 F：综合候选评分与选择

目的：使用整个识别链路选择最可信的面板，而不是仅依赖外框。

初始综合分数建议：

```text
内部锚点与面板结构       35%
普通卡片分割完整度       25%
现有分类与模板分数       25%
英雄装备与战宠一致性     15%
```

一致性检查包括：

- 四列英雄是否都生成两个装备框和一个战宠框；
- 每列两件装备是否存在同一英雄归属组合；
- 四个战宠是否获得合理候选；
- 普通卡片是否位于正确功能区域；
- 是否出现多个区域分类分数同时下降；
- 候选框是否越界、重叠或具有异常间距。

选择规则：

1. 选择总分最高的候选作为最终分割结果。
2. 保存第二、第三候选及与第一名的分差，供调试使用。
3. 第一名总分过低或与第二名过于接近时，显示“面板定位不确定”提示，但仍提供最佳结果和手动调整入口。
4. 在样本集稳定前，不设置过早的强制淘汰阈值。

### 阶段 G：手动面板容错

目的：保留现有交互，同时避免用户进行像素级盲调。

任务：

1. 用户提交的面板框作为最高优先级粗候选。
2. 在手动框附近搜索小范围平移和四边变化，初始范围可设为面板宽高的约 1%～2%。
3. 使用与自动候选相同的内部结构、单卡分割和识别评分。
4. 最终显示精修后的面板框和全部单卡框。
5. 不增加区域或单卡拖拽控件。

完成条件：用户手动框存在肉眼难以避免的小误差时，仍能稳定产生英雄、装备和战宠框。

## 8. 代码改动规划

### `src/recognition/panelLocator.ts`

- 保留现有颜色组件和边缘工具。
- 将单一面板返回值改造为候选生成接口。
- 拆分候选生成、候选去重和粗评分。
- 保留兼容包装函数，降低调用方一次性改动风险。

### 新增 `src/recognition/panelRegistration.ts`

- 定义标准内部锚点。
- 实现高分辨率结构评分。
- 实现轴对齐缩放和平移精修。
- 输出分项证据，避免只返回不可解释的总分。

### `src/recognition/preflight.ts`

- 组织游戏画面裁剪、粗候选生成和高分辨率精修。
- 保存候选列表、最终选择和置信度。
- 手动面板覆盖改为精修种子，而不是直接作为最终裁剪。

### `src/recognition/cardAnalysis.ts`

- 支持对多个分割候选执行现有普通卡片检测。
- 汇总卡槽结构和识别评分。
- 避免在候选选择前丢弃诊断信息。

### `src/recognition/heroSubcardAnalysis.ts`

- 将固定小矩形改为“标准位置 + 英雄区域共享局部修正”。
- 输出所有分割框和低分识别候选。
- 将完整性过滤延后到最终配兵结果生成阶段。

### `src/recognition/visualEngine.ts`

- 保持最终配兵结果的严格要求。
- 区分分割失败、装备归属冲突和战宠识别不足。
- 不使用最终英雄数组作为唯一的分割框来源。

### `src/components/RecognitionOverlay.tsx`

- 调试模式显示所有普通卡片与英雄子卡分割框。
- 使用样式区分“已分割未识别”和“已完整识别”。
- 保持现有整体面板手动调整交互不变。

## 9. 测试计划

### 9.1 单元测试

- 关闭按钮被白色 X 分割。
- 游戏内其他红色角标干扰。
- 左右黑边宽度不一致。
- 字幕靠近面板底边。
- 面板外框与内部木纹边缘同时存在。
- 标准布局发生轻微水平或垂直拉伸。
- 四列英雄存在统一偏移。
- 手动面板四条边分别发生 ±1% 和 ±2% 扰动。
- 战宠分数低于阈值时仍保留分割框。
- 装备归属冲突时仍保留装备框。

### 9.2 样本回归

对 `recognition-samples/test_data` 的 1～13 验证：

- 游戏画面裁剪稳定。
- 最终面板候选稳定。
- 五个区域均位于正确内容范围。
- 普通卡片数量与当前正确基准一致。
- 四列英雄、八件装备、四个战宠均产生候选框。
- 样本 11、12 均产生四列完整英雄分割结果。

### 9.3 格式与扰动回归

- PNG、JPEG 95、JPEG 85、WebP。
- 原始尺寸、75% 缩放和 50% 压力样本。
- 左右或上下增加黑边。
- 字幕位置发生小幅变化。
- 对正确面板框施加随机平移和四边扰动。

### 9.4 下游回归

- 兵种、法术、攻城机器和援兵分类不因分割改造回退。
- 装备归属与战宠识别结果保持或改善。
- 配兵容量校验和链接生成不修改既有行为。
- 完整单元测试和生产构建通过。

## 10. 验收标准

必须同时满足：

1. 样本 1～13 均能自动完成五个区域和单卡级分割。
2. 样本 11、12 均输出四列英雄、八件装备和四个战宠框。
3. 当前已经正确的普通卡片分割数量不得回退。
4. 正确面板框发生约 ±1% 边界扰动后，单卡数量和主要识别结果保持一致。
5. 手动框不再需要几个像素级的反复调整才能出现英雄框。
6. 分割成功但识别失败时，候选框仍然可见且失败原因可区分。
7. PNG、JPEG 和 WebP 常规输入之间不出现明显的候选跳变。
8. 不新增模型文件、模型加载时间或额外训练流程。

## 11. 实施顺序与提交边界

建议按以下顺序分批实施，每个阶段均保持可回退：

1. 诊断数据与调试框，不改变生产选择结果。
2. 多面板候选生成，继续使用旧候选作为默认结果。
3. 内部结构配准，在测试中并行比较新旧候选。
4. 启用综合评分选择最终候选。
5. 英雄区域共享局部配准。
6. 手动面板容错精修。
7. 全量样本、格式变体和扰动回归。
8. 功能稳定后再分析性能热点并优化。

每一阶段都应单独记录样本 1～13 的面板坐标、卡槽数量、英雄完整度和耗时，避免多个变量同时变化后无法定位回归原因。

## 12. 风险与控制措施

### 候选搜索导致运行时间上升

控制方式：限制粗候选数量；先用结构分数淘汰明显错误候选；后续再对热点进行缓存、降采样和批量分类优化。

### 识别分数反向强化错误分割

控制方式：识别分数只能占综合评分的一部分；必须同时满足合理卡片边缘、间距和区域位置；保留候选分项证据方便诊断。

### 针对 11、12 过拟合

控制方式：每次参数调整必须同时执行 1～13、格式变体和边界扰动测试；不允许通过文件名、设备名或固定分辨率选择布局。

### 英雄小框独立搜索吸附到错误图标

控制方式：四列英雄共享位置和间距参数，装备共享行基线，只允许有限的局部残差修正。

### 中间类型改造影响现有流程

控制方式：先增加兼容包装函数；分割结果和最终识别结果并行存在；逐个替换调用点，不一次性删除旧接口。

## 13. 完成定义
